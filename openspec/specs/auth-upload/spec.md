# CampusClaw 迭代 1：认证、授权与知识库入库

本文件基于本次提供的五份第 3 课讲义整理；原讲义引用的第 2 课 change 四件套未提供，因此这是此独立项目的验收契约。

## R1 认证
- 无会话访问 `/api/me` 和任何材料接口返回 401，不包含材料标题或正文。
- 教师和学生通过用户名及口令登录；错误账号、错误口令与限流后的失败均为同样的 401 JSON。
- 登录签发服务端随机会话，通过 HttpOnly、SameSite=Lax Cookie 传递；登出删除会话，旧 Cookie 立即 401。
- 每个请求从数据库重新读取用户角色和固定班级；未知角色拒绝。

## R2 授权
- 教师可上传、查看、下载本班材料；学生可查看、下载本班材料，上传返回 403。
- 请求体、查询参数和客户端显示内容都不能决定角色或班级。

## R3 隔离
- 列表和标题搜索由数据库按会话班级筛选；班 A 和班 B 互不可见。
- 详情和文件下载均用 id 与班级条件联合查询。跨班、缺失 id 均返回相同的 404 JSON。
- 上传原文件不可用 `/uploads` 静态路径直接读取。

## R4 上传与入库
- 只允许 `.txt` 和 `.md`，最多 2 MiB，正文必须是非空有效 UTF-8 且不能包含 NUL。
- 扩展名非法返回 415，超限返回 413，正文非法返回 422；这些失败不产生材料、知识条目或原文件。
- 服务端生成随机存储名；将材料元数据与 knowledge_entries 正文在一个数据库事务内写入；失败清理原文件。
- 本班学生能读到教师上传的正文，Markdown 展示不执行用户 HTML。

## R5 页面
- 登录页与材料页；`/api/me` 识别身份，401 返回登录页；本班搜索、列表/网格、深浅色、响应式排版、上传反馈和 Markdown GFM 展示。
- 前端隐藏上传入口只做体验；访问控制必须由 API 实施。

## R6 安全与部署
- bcrypt 哈希保存口令，数据库口令、预置口令、SESSION_SECRET 仅从环境读取，缺失启动失败；密钥不提交。
- POST 的跨站来源拒绝；未登录、跨班和限流响应不暴露详细原因。
- `/health` 不查数据库，只表示进程存活；数据库故障时业务接口为 503。
- Compose 只映射 web 端口，db 与 api 不映射到宿主；uploads 只挂载到 api。

## Non-goals
超级管理员、向量检索、RAG 问答、作业系统、多副本、外部校园 SSO 均不在本迭代。
